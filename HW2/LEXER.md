# Лексер Funny (HW1): регулярные выражения → НКА → ДКА → минимальный ДКА

Python ≥ 3.10, только стандартная библиотека (ничего ставить не нужно).

## Быстрый старт

```bash
python3 -m funny_lexer all        # build + test + REPORT.md
```

Отдельные команды:

```bash
python3 -m funny_lexer build                # построить автоматы, выгрузить таблицы в out/
python3 -m funny_lexer test [-v]            # прогнать тесты (код возврата 1, если есть FAIL)
python3 -m funny_lexer report               # пересобрать REPORT.md из реального прогона
python3 -m funny_lexer lex prog.fn          # разбить файл на токены ('-' = stdin)
python3 -m funny_lexer lex prog.fn --table out/dfa.json --keep-skip
python3 -m unittest discover -s tests -v    # те же тесты через unittest
make all | build | test | report | unittest | clean
```

Общие флаги: `--spec FILE` (своя спецификация токенов), `--out DIR` (каталог артефактов).

Пример:

```
$ echo 'x = 01; // ok' | python3 -m funny_lexer lex -
     0  IDENT          'x'
     2  ASSIGN         '='
     4  BAD_INT        '01'
     6  SEMI           ';'
```

## Структура

```
spec/funny.tokens        вход: регулярные выражения токенов (порядок = приоритет)
funny_lexer/
  regex.py               разбор regex → AST; алфавит ASCII + символ OTHER (non-ASCII)
  spec.py                чтение спецификации, флаги @skip / @error
  nfa.py                 конструкция Томпсона + симуляция НКА (эталон для тестов)
  dfa.py                 классы символов, subset construction, Хопкрофт, проверки (Мур, эквивалентность)
  pipeline.py            склейка этапов + статистика
  export.py              JSON / CSV
  lexer.py               ★ runtime-лексер по таблице (без зависимостей) — для T0
  testing.py             прогон кейсов, покрытие алфавита, property-тесты
  report.py, cli.py
tests/cases.json         тесты: вход + ожидаемый результат
tests/test_hw1.py        unittest-обёртка
out/                     артефакты (генерируются build/test)
REPORT.md                отчёт (генерируется report)
```

## Как это работает

1. **Спецификация.** Токены сверены со спецификацией языка Funny (funny.md): идентификаторы — латинская
   буква, затем буквы и цифры (без `_`); ключевые слова из спецификации плюс `function`, `assert`, `assume`,
   `length` из списка задания HW1; импликация записывается в ASCII как `->` (символ `→` вне алфавита).
   Строка `[@skip|@error] ИМЯ = regex`. `WS` и `COMMENT` помечены `@skip`.
   Числа с ведущим нулём (`00`, `01`) описаны отдельным токеном `@error BAD_INT = 0[0-9]+`:
   по maximal munch он длиннее, чем `INT "0"`, поэтому `01` целиком становится ошибкой, а не `0` + `1`.
2. **НКА (Томпсон).** Фрагмент на каждый токен, общий старт по ε. Конец фрагмента помечен приоритетом токена.
3. **Классы символов.** 129 символов (ASCII + `OTHER`) разбиваются на классы, которые НКА не различает → 45 колонок вместо 129.
4. **ДКА (подмножества).** Метка состояния — токен с наименьшим приоритетом среди принимающих НКА-состояний
   (так ключевые слова побеждают `IDENT`). Пустое множество = ловушка, автомат полный.
5. **Хопкрофт.** Начальное разбиение — по имени токена (а не просто «принимает / нет»).
   Затем BFS-перенумерация: старт = 0, ловушка — последнее состояние.
6. **Проверки корректности** (входят в `test`): Хопкрофт ≡ Мур по числу состояний; мин. ДКА эквивалентен
   исходному (обход произведения); в мин. ДКА нет эквивалентных пар; на 1500 случайных строк (seed 2026)
   совпадают НКА, ДКА и мин. ДКА, а табличный лексер выдаёт те же токены, что и эталонный лексер на НКА.

## Ловушка

Ловушка — непринимающее состояние с петлями по всем классам. В неё попадает любой символ вне языка из старта
(`@ # $ ! …`, управляющие кроме `\t \n \r`), **любой non-ASCII символ из любого состояния** (включая комментарий)
и недопустимые продолжения. Лексер откатывается к последнему принимающему состоянию, а если его не было —
выдаёт `ERROR` на один символ и продолжает.

## Артефакты в `out/`

| Файл | Содержимое |
|---|---|
| `dfa.json` | **основной экспорт**: минимальный ДКА (формат ниже) |
| `dfa_unminimized.json` | ДКА после subset construction, тот же формат — для сравнения |
| `transitions.csv` | таблица переходов: строка = состояние, колонка = класс символов |
| `char_classes.csv` | код символа → класс |
| `stats.json` | размеры автоматов |
| `test_results.json` | каждый тест: вход, ожидание, факт, PASS/FAIL |

Формат `dfa.json` (`funny-dfa/1`):

```jsonc
{
  "alphabet": {"size": 129, "ascii_size": 128, "other_symbol": 128},
  "tokens": [{"name": "KW_FUNCTION", "kind": "token", "priority": 0, "regex": "\"function\""}, ...],
  "start": 0, "trap": 122, "num_states": 123, "num_classes": 45,
  "char_classes": [/* 129 чисел: символ -> класс; код >= 128 смотреть в [128] */],
  "accepting": {"1": "WS", "3": "LPAREN", ...},
  "transitions": [[/* 45 переходов состояния 0 */], ...]
}
```

Шаг автомата: `state = transitions[state][char_classes[min(ord(ch), 128)]]`.

## Подключение в лексер проекта (T0)

`funny_lexer/lexer.py` зависит только от таблицы, его можно скопировать в проект вместе с `out/dfa.json`:

```python
from lexer import TableLexer
lx = TableLexer.from_json("dfa.json")
for tok in lx.tokens(source):                  # Token(kind, lexeme, pos); WS/COMMENT уже отброшены
    if lx.is_error(tok): ...                   # ERROR или BAD_INT
```

`pos` — смещение в символах; строки/столбцы добавятся в HW2. Если язык расширится (новые операторы
или ключевые слова) — правится только `spec/funny.tokens`, затем `make all`.

## Тесты

`tests/cases.json` — 206 ручных кейсов двух видов:
`match` (вся строка должна быть ровно одним токеном, `null` = отказ) и `tokens` (ожидаемый поток токенов).
Плюс автоматически: каждый из 128 ASCII-символов и 7 non-ASCII по одному (ожидания заданы явно в `testing.py`)
и 6 property-проверок. Итого 347 проверок. Покрыты все обязательные сценарии задания: пустая строка;
пробелы/табы/CRLF; `0`, `00`, `01`; идентификаторы (`_` по спецификации запрещён → ошибка); все ключевые слова и «почти ключевые»;
все операторы и разделители; комментарии до конца строки (LF и CRLF); non-ASCII → ловушка.
