# Грамматика Funny для LL(1)-парсера (HW2) 

Финальная грамматика в машинно-проверяемом виде — [`grammar/funny.ll1`](grammar/funny.ll1).
Её проверяет команда `python3 -m funny_parser grammar`: считает FIRST/FOLLOW, строит
LL(1)-таблицу (`out/ll1_table.csv`, `out/ll1_first_follow.txt`) и печатает конфликты.
Терминалы грамматики — это имена токенов лексера HW1, и проверка сверяет их со `spec/funny.tokens`.

Итог проверки: **45 нетерминалов, 45 терминалов, 91 продукция, 1 конфликт** (висячий `else`, см. п. 4).

## 0. Лексика: терминалы грамматики

Терминалы (`IDENT`, `INT` и т.д.) — это токены лексера из HW1, их регулярные выражения
заданы в [`spec/funny.tokens`](spec/funny.tokens). В EBNF ниже ключевые слова и знаки
записаны в кавычках (`"if"`, `"("`), а токены с переменным текстом — именами:

```ebnf
IDENT   = letter { letter | digit } ;          (* латинская буква, потом буквы и цифры; '_' нельзя *)
INT     = "0" | nonzero { digit } ;            (* без ведущих нулей: 0, 7, 42 *)
letter  = "A" | ... | "Z" | "a" | ... | "z" ;
digit   = "0" | nonzero ;
nonzero = "1" | ... | "9" ;
```

Ключевые слова (`if`, `while`, `int`, `true`, …) имеют приоритет над `IDENT`: `if` — ключевое
слово, а `iff` — идентификатор. Между любыми токенами допустимы пропуски (`WS`) и комментарии
(`COMMENT`), в грамматике они не пишутся:

```ebnf
WS      = ( " " | "\t" | "\r" | "\n" ) { " " | "\t" | "\r" | "\n" } ;
COMMENT = "//" { любой ASCII-символ, кроме "\r" и "\n" } ;
```

Соответствие имён токенов (они используются в `grammar/funny.ll1`) их тексту:

| Токен | Текст | Токен | Текст | Токен | Текст |
|---|---|---|---|---|---|
| `IDENT` | имя | `LPAREN` | `(` | `EQ` | `==` |
| `INT` | число | `RPAREN` | `)` | `NE` | `!=` |
| `KW_<слово>` | ключевое слово, например `KW_IF` = `if` | `LBRACKET` | `[` | `LT` | `<` |
| `ASSIGN` | `=` | `RBRACKET` | `]` | `LE` | `<=` |
| `PLUS` | `+` | `LBRACE` | `{` | `GT` | `>` |
| `MINUS` | `-` | `RBRACE` | `}` | `GE` | `>=` |
| `STAR` | `*` | `COMMA` | `,` | `ARROW` | `->` |
| `SLASH` | `/` | `SEMI` | `;` | `FAT_ARROW` | `=>` |
| `COLON` | `:` | `BAR` | `\|` | `EOF` / `$` | конец файла |

## 1. Грамматика в EBNF (читаемая версия)

```ebnf
module      = decl { decl } ;
decl        = function | formula ;
function    = [ "function" ] IDENT "(" [ varDefs ] ")"
              [ "requires" expr ]
              "returns" varDefs
              [ "ensures" expr ]
              [ "uses" varDefs ]
              statement ;
formula     = IDENT "(" [ varDefs ] ")" "=>" expr ;
varDefs     = varDef { "," varDef } ;
varDef      = IDENT ":" type ;
type        = "int" [ "[" "]" ] ;

statement   = block | if | while | assert | assume | assign ;
block       = "{" { statement } "}" ;
if          = "if" "(" expr ")" statement [ "else" statement ] ;
while       = "while" "(" expr ")" [ "invariant" expr ] statement ;
assert      = "assert" expr ";" ;
assume      = "assume" expr ";" ;
assign      = IDENT "=" expr ";"                          (* простое *)
            | IDENT "[" expr "]" "=" expr ";"             (* элемент массива *)
            | IDENT "," IDENT { "," IDENT } "=" expr ";"  (* кортежное, справа — вызов *)

expr        = orExpr [ "->" expr ] ;                      (* правоассоциативна *)
orExpr      = andExpr { "or" andExpr } ;
andExpr     = notExpr { "and" notExpr } ;
notExpr     = "not" notExpr | cmpExpr ;
cmpExpr     = addExpr [ relop addExpr ] ;                 (* без цепочек *)
relop       = "==" | "!=" | "<" | "<=" | ">" | ">=" ;
addExpr     = mulExpr { ( "+" | "-" ) mulExpr } ;
mulExpr     = unary { ( "*" | "/" ) unary } ;
unary       = "-" unary | primary ;
primary     = INT | "true" | "false"
            | IDENT [ "(" [ args ] ")" | "[" expr "]" ]
            | "length" "(" [ args ] ")"
            | ( "forall" | "exists" ) "(" varDef "|" expr ")"
            | "(" expr ")" ;
args        = expr { "," expr } ;
```

## 2. Приоритеты и ассоциативность

| Уровень (от слабого к сильному) | Операции | Ассоциативность |
|---|---|---|
| 1 | `->` (импликация) | правая: `a -> b -> c` = `a -> (b -> c)` |
| 2 | `or` | левая |
| 3 | `and` | левая |
| 4 | `not` | префиксный |
| 5 | `==` `!=` `<` `<=` `>` `>=` | нет: `a < b < c` — ошибка |
| 6 | `+` `-` | левая |
| 7 | `*` `/` | левая |
| 8 | унарный `-` | префиксный |

Всё как в `docs/funny.md`: унарный минус сильнее всех; `*` `/` сильнее `+` `-`;
`not` → `and` → `or` → `->`. Сравнение стоит между `not` и арифметикой, поэтому
`not a < b` означает `not (a < b)`, а `not a < b and c < d` — `(not (a < b)) and (c < d)`.

Приоритеты заданы самой структурой грамматики (уровень = нетерминал), а левая
ассоциативность — циклом `while` в функции разбора (левая рекурсия устранена).

## 3. Как грамматика приведена к LL(1)

1. **Устранена левая рекурсия.** В спецификации `expr = expr "+" expr | …` — так рекурсивный
   спуск зациклится. Заменено уровнями `addExpr = mulExpr { "+" mulExpr }`.
2. **Левая факторизация.**
   * функция и формула начинаются одинаково `IDENT "(" params ")"` — общий префикс вынесен,
     дальше выбор по одному токену: `=>` — формула, `requires`/`returns` — функция;
   * три формы присваивания начинаются с `IDENT` — выбор по следующему токену `=`, `[` или `,`;
   * `IDENT` в выражении: `(` — вызов, `[` — элемент массива, иначе — переменная.
3. **Единая грамматика для expr / condition / predicate.** В спецификации это три разных
   нетерминала, но вместе они **не LL(1)**: увидев `(`, нельзя решить, начинается ли
   `(a + b) > c` (скобка вокруг выражения) или `(a > b) and c` (скобка вокруг условия);
   увидев `p(x)`, нельзя решить, вызов это функции или ссылка на формулу. Поэтому разбор идёт
   по одной грамматике со всеми операциями, а после разбора отдельный проход
   (`funny_parser/sortcheck.py`) проверяет вид каждого выражения по месту:
   * **целое** (правая часть присваивания, индекс, аргументы): числа, переменные, `a[i]`,
     вызовы, `- + * /`;
   * **условие** (`if`, `while`): `true`/`false`, сравнения, `not`/`and`/`or`/`->`;
   * **предикат** (`requires`, `ensures`, `invariant`, `assert`, `assume`, тело формулы):
     условие + кванторы + ссылки на формулы (`p(x)` в логической позиции → `FormulaRef`).

   В итоге принимается ровно язык спецификации, а ошибки вида
   («`if (x)` — нужно логическое выражение») сообщаются с позицией.

## 4. Единственный конфликт: висячий `else`

`else_opt -> KW_ELSE statement | ε`: токен `else` входит и в FIRST первой альтернативы,
и в FOLLOW(`else_opt`). Конфликт разрешён в пользу `KW_ELSE` — парсер жадно забирает `else`,
и он относится к **ближайшему** `if`. Это ровно то, что требует спецификация
(«nested conditional statements are right-associative»); тест — `tests/parser/positive/05_dangling_else.fn`.

## 5. Отклонения от спецификации (`docs/funny.md`)

| # | Что | Почему |
|---|---|---|
| 1 | Единая грамматика выражений + проверка видов после разбора | иначе не LL(1) (п. 3); принимаемый язык тот же |
| 2 | Импликация пишется `->`, а не `→` | алфавит ASCII (HW1); в тексте спецификации тоже `a -> b` |
| 3 | `->` разрешена и в предикатах | в EBNF предиката её нет, но предикаты — расширение условий, а в формулах она нужна (`forall(i \| … -> …)`) |
| 4 | Операторы `assert P;` и `assume P;` | требование HW2, в спецификации их нет; аргумент — предикат |
| 5 | Необязательное `function` перед функцией | `function` — ключевое слово из HW1, иначе его нельзя было бы использовать |
| 6 | `length` — ключевое слово лексера | разбирается как вызов `Call("length", …)`, как встроенная функция спецификации |
| 7 | Пустой модуль — ошибка | требование HW2 («пустой ввод» — негативный тест) |
| 8 | `a[i] = e;` в AST — `Assign(a, ArrayStore(a, i, e))` | «обновление как сахар для функционального копирования»: новый массив = старый с заменённым элементом |
| 9 | В кортежном присваивании справа проверяется вызов | в грамматике там `expr`, ограничение проверяется после разбора с понятным сообщением |
| 10 | Числа с ведущим нулём (`01`) — ошибка | решение HW1; разбор продолжается, число считается обычным |

**Не проверяется парсером** (это семантика, следующие HW): типы `int`/`int[]`, объявлены ли
имена и формулы, только чтение параметров, «локальные переменные только `int`», вызов
многозначных функций в выражениях, число аргументов, уникальность имён, диапазон int32.

## 6. Обработка ошибок (режим паники)

* Сообщение: `файл:строка:столбец: ошибка: ожидалось X, найдено Y`. Для незакрытых скобок
  указывается, где была открывающая: `ожидалось ')' для '(' из 2:6`.
* **Оператор с ошибкой** пропускается до `;` (включительно), `}` или начала следующего
  оператора (`if`, `while`, `assert`, `assume`, `{`), и разбор блока продолжается.
* **Объявление с ошибкой** пропускается до начала следующего объявления: `function` или
  `IDENT (` на нулевой глубине скобок в начале строки / после `}` / `;`.
* **Лексические ошибки**: недопустимые символы подряд дают одно сообщение; non-ASCII внутри
  комментария — одно сообщение, остаток строки пропускается.
* Две ошибки в одной позиции не дублируются; после 100 ошибок разбор останавливается.
* **Защита от зацикливания:** каждый шаг восстановления съедает хотя бы один токен, а число
  шагов парсера ограничено (`50 × число токенов`). Тест `fuzz` портит позитивные программы
  600 раз и проверяет, что парсер не падает и не зацикливается.
