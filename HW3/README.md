# HW3. Семантические проверки и типы Funny

Python ≥ 3.10, только стандартная библиотека. Проект продолжает HW1 (лексер) и HW2 (парсер):

```
текст → лексер (HW1) → парсер (HW2) → семантический анализ (HW3) → аннотированный AST + ошибки
```

## Быстрый старт

```bash
python3 -m funny_sema test                           # тесты HW3 (74 проверки)
python3 -m funny_sema check examples/typed.fn        # аннотированный AST: типы + таблицы символов
python3 -m funny_sema check examples/type_errors.fn  # 11 ошибок за один запуск
```

## Команды

```bash
python3 -m funny_sema check FILE                 # аннотированный AST (текст) или ошибки
python3 -m funny_sema check FILE --json          # AST с типами + символы + ошибки в JSON
python3 -m funny_sema check FILE --partial       # при ошибках всё равно вывести AST
python3 -m funny_sema check FILE --allow-array-locals   # разрешить локальные int[] (расширение)
python3 -m funny_sema test [-v]                  # тесты семантики
python3 -m funny_parser test                     # тесты парсера (HW2, 141)
python3 -m funny_lexer test                      # тесты лексера (HW1, 347)
python3 -m unittest discover -s tests -v         # всё через unittest
make test | sema | parser | lexer | unittest
```

`FILE` можно заменить на `-` (чтение из терминала). Код возврата: 0 — без ошибок, 1 — есть ошибки, 2 — файл не найден.

## Что проверяется

**Имена и таблицы символов** (2 балла):
- неизвестные переменные и функции (с подсказкой «возможно, имелось в виду …»);
- повторные объявления функций и формул (перегрузок нет), параметров, результатов, локальных;
- области видимости: `requires` видит только параметры, `ensures` — ещё и результаты, тело — всё; переменная квантора видна только в нём и не может совпадать с видимым именем;
- использование вне области видимости;
- присваивание параметру, путаница функции, формулы и переменной.

**Типы** (4 балла):
- `int`, `int[]`, `bool` — правила для всех выражений и операторов;
- вызовы: проверяется число аргументов и их типы по сигнатуре, в том числе для `length` и формул;
- функции с несколькими результатами не используются в выражениях; кортежное присваивание сверяется по числу и типам;
- кванторы и формулы допустимы только в предикатах;
- константы проверяются на диапазон int32;
- локальные переменные по спецификации только `int`.

**Бонус — вывод типов локальных**: `uses i, acc` без типов. Тип выводится унификацией из первого места, где он однозначен (обычно первое присваивание). Противоречие или невозможность вывода — ошибка с указанием, где тип был выведен.

Подробности, правила типизации и ограничения — в [`SEMANTICS.md`](SEMANTICS.md).

## Структура

```
funny_sema/
  types.py      типы, переменные типов, unify (union-find, проверка вхождения)
  symbols.py    Symbol, Scope — таблицы символов и области видимости
  checker.py    ★ проверки имён и типов, вывод типов локальных
  pipeline.py   check_program(text): лексер → парсер → семантика
  output.py     аннотированный AST: текст и JSON
  testing.py    тесты;  cli.py — команды
funny_parser/   парсер HW2 (добавлено: uses без типа, поля аннотаций в узлах)
funny_lexer/    лексер HW1
tests/sema/
  positive/*.fn + *.out   корректные программы и эталонный аннотированный AST
  negative/*.fn + *.err   программы с ошибками и ожидаемые сообщения
examples/       typed.fn, type_errors.fn (+ примеры HW2)
```

## API для HW4

```python
from funny_sema import check_program
r = check_program(text)
r.diags        # список ошибок (line, col, message, phase)
r.module       # AST: у каждого выражения node.ty, у имён node.ref
r.tables       # имя функции -> [Symbol(name, kind, type, line, col)]
r.signatures   # имя -> Signature(kind, params, returns)
```

## Тесты

`python3 -m funny_sema test` — 74 проверки:

| Группа | Сколько | Что проверяет |
|---|---|---|
| positive | 10 | корректные программы (явные типы, массивы, кортежи, формулы, рекурсия, вывод типов, области видимости, границы int32, пространства имён, флаг `int[]`-локальных); аннотированный AST == `*.out` |
| negative | 20 | неизвестные имена, повторные объявления, несовместимые типы, неверное число и типы аргументов, многозначные функции, параметры только для чтения, области видимости, кванторы и формулы вне предикатов, затенение, диапазон int32, противоречия и невозможность вывода, нет приведений int↔bool, синтаксис раньше семантики, много ошибок сразу; сообщения == `*.err` |
| diagnostics | 21 | у каждой ошибки есть корректная позиция и понятный текст; анализ не останавливается после первой ошибки |
| unify | 11 | унификация: связывание, цепочки, противоречия, структурные массивы, проверка вхождения |
| json | 10 | тип есть у каждого выражения аннотированного AST |
| fuzz | 2 | 400 случайных порч (имена, типы, числа): анализатор не падает, позиции есть всегда |

Плюс тесты HW2 (141) и HW1 (347) — они по-прежнему проходят.
