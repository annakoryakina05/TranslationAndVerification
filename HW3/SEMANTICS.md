# Отчёт HW3: семантические проверки и типы Funny

Код: `funny_sema/` — `types.py` (типы и унификация), `symbols.py` (таблицы символов),
`checker.py` (проверки), `output.py` (аннотированный AST), `pipeline.py` (весь конвейер).

## 1. Поддерживаемые типы

| Тип | Где встречается | Примеры |
|---|---|---|
| `int` | числа, переменные, `a[i]`, результат `+ - * /`, `length` | `x`, `a[i] + 1` |
| `int[]` | параметры, результаты (и локальные с флагом) | `a: int[]` |
| `bool` | условия и предикаты; переменных типа `bool` в Funny нет | `x > 0`, `true`, `p(x)` |
| сигнатура функции | `(int, int[]) -> (int, int)` | `divmod` |
| сигнатура формулы | `(int[]) -> bool`, только в предикатах | `sorted(a)` |
| встроенная `length` | `(int[]) -> (int)` | `length(a)` |

Служебные типы:
- **переменная типа `?`** — тип ещё не известен, это локальная переменная без аннотации (бонус);
- **`<ошибка>`** — подставляется после уже выданной ошибки и совместим со всем, чтобы одна ошибка не порождала каскад.

Типа `string` и других типов в Funny нет. **Перегрузки и неявные приведения не поддерживаются**: имя функции уникально, `int` и `bool` между собой не преобразуются, поэтому `if (x)` — ошибка. Так требует спецификация; тесты `negative/03` и `negative/18` это проверяют.

## 2. Правила типизации

Запись: «если части имеют такие типы, то выражение имеет такой тип».

| Конструкция | Требования | Тип |
|---|---|---|
| `123` | от −2147483648 до 2147483647 | `int` |
| `true`, `false` | — | `bool` |
| `x` | `x` объявлена и видна в этом месте | тип `x` |
| `a[i]` | `a : int[]`, `i : int` | `int` |
| `-e` | `e : int` | `int` |
| `e1 + e2`, `-`, `*`, `/` | оба `int` | `int` |
| `e1 < e2`, `<= > >= == !=` | оба `int` (массивы не сравниваются) | `bool` |
| `not p` | `p : bool` | `bool` |
| `p and q`, `or`, `->` | оба `bool` | `bool` |
| `f(e1..en)` | `f` — функция, n аргументов нужных типов, ровно 1 результат | тип результата |
| `p(e1..en)` в предикате | `p` — формула, n аргументов нужных типов | `bool` |
| `forall/exists(i: T \| p)` | только в предикате; имя `i` не занято; `p : bool` | `bool` |

| Оператор | Требования |
|---|---|
| `x = e;` | `x` — результат или локальная (не параметр); тип `e` = тип `x` |
| `a[i] = e;` | `a : int[]`, можно присваивать; `i, e : int`. В AST: `a = store(a, i, e)` |
| `x, y = f(...);` | `f` — функция, число результатов = число переменных, типы совпадают, имена разные |
| `if (c)`, `while (c)` | `c : bool`, без кванторов и формул |
| `invariant`, `assert`, `assume`, `requires`, `ensures`, тело формулы | предикат: `bool`, можно кванторы и формулы |

## 3. Имена и области видимости (таблицы символов)

- **Модуль:** функции, формулы и `length` в одном пространстве имён. Порядок объявления не важен: сначала собираются все сигнатуры, поэтому работает вызов функции, объявленной ниже, и взаимная рекурсия.
- **Функция:** параметры, результаты и локальные переменные. Блоки `{ }` новых областей не создают, потому что в Funny все переменные объявлены в заголовке.
- **Видимость по частям функции** (порядок частей заголовка задаёт области, как сказано в спецификации):

  | Часть | Видны |
  |---|---|
  | `requires` | параметры |
  | `ensures` | параметры, результаты |
  | тело, `invariant`, `assert`, `assume` | параметры, результаты, локальные |
  | тело формулы | параметры формулы |

  Использование результата в `requires` или локальной в `ensures` — ошибка: имя ещё не объявлено или недоступно.
- **Квантор** открывает вложенную область. Его переменная не может совпадать ни с одним видимым именем, это требование спецификации. Соседние кванторы могут использовать одно и то же имя.
- Переменные и функции живут в разных пространствах имён: `x` — переменная, `x(...)` — вызов.

Проверяется:
- неизвестные имена (с подсказкой «возможно, имелось в виду …»);
- повторные объявления функций и формул, а также параметров, результатов и локальных;
- использование вне области видимости;
- присваивание параметру (параметры только для чтения, включая элементы массива);
- функция или формула, использованная как переменная, и формула, использованная как функция;
- переменная квантора, совпадающая с уже видимым именем.

## 4. Унификация и вывод типов локальных (бонус)

Тип локальной переменной можно не писать: `uses i, acc`. Грамматика для этого расширена: `local_def -> IDENT type_opt`, и она по-прежнему LL(1).

Как это работает (`types.py`):
1. Такой переменной даётся **переменная типа** `?`.
2. Каждое сравнение «фактический тип = ожидаемый» выполняется через `unify(a, b)`. Если одна сторона — `?`, она **связывается** с другой, и запоминается место, где это произошло.
3. Типы структурные: `unify(?[], int[])` даёт `? = int`. Есть проверка вхождения, так что `? = ?[]` невозможно.
4. Связанные переменные хранятся по схеме union-find: `u = v; v = x;` выводит `int` для обеих.

Откуда берётся тип: из **первого места в тексте, где он однозначен**. Обычно это первое присваивание (`i = 0` → `int`), но может быть и использование: `r = t + 1` → `t : int`, `length(t)` → `t : int[]`. Это обобщение правила «тип по первому присваиванию», и оно корректно, потому что Funny разрешает читать переменную до присваивания.

Ошибки вывода:
- **противоречие**: тип уже выведен, а новое использование требует другого. В сообщении указано, где тип был выведен: `присваивание 'x': ... (тип 'x' выведен в 3:3)`;
- **невозможность вывода**: к концу функции тип так и остался `?` (переменная не используется) → `не удалось вывести тип ...`;
- **правило спецификации**: локальные переменные могут быть только `int`. Если выведен `int[]`, это ошибка. Флаг `--allow-array-locals` (или первая строка файла `// sema: allow-array-locals`) снимает это ограничение как расширение языка.

## 5. Диагностика

- Формат: `файл:строка:столбец: ошибка (имена|типы): текст`. Позиция — первый токен узла.
- **Анализ не останавливается на первой ошибке**: собираются все ошибки во всех функциях. Тест `negative/20_many_errors.fn` находит 11 ошибок за один запуск.
- Против каскадов: после ошибки выражение получает тип `<ошибка>`, совместимый со всем; одна и та же ошибка в одной позиции не повторяется.
- Если есть **синтаксические** ошибки, семантический анализ не запускается. Дерево неполное, и проверка имён дала бы ложные ошибки вроде «неизвестная функция» для функции, которую парсер пропустил. Об этом выводится отдельное сообщение.

## 6. Ограничения

- Не проверяется, что каждому результату функции что-то присвоено (это анализ потоков данных, следующие этапы).
- Деление на ноль и выход за границы массива — ошибки времени выполнения, статически не проверяются.
- Переполнение int32 проверяется только для констант, не для вычислений.
- Вывод типов — только для локальных переменных; типы параметров и результатов всегда пишутся явно (так требует задание).
- Рекурсия в формулах (формула ссылается на себя) не запрещена; её смысл — забота верификатора.
